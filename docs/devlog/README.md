# Development Log

Create one file per accepted phase or significant experiment.

## Required structure

1. Problem
2. First principle
3. Alternatives considered
4. Decision and trade-offs
5. Smallest implemented slice
6. Experiment or failure scenario
7. Reproducible evidence
8. What failed or changed
9. Limitations
10. Next question

A devlog is not a marketing changelog. Never insert unexecuted commands, fabricated metrics, or claims not backed by repository artifacts.
